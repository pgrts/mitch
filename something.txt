4) Tracking the value correctly (and updating visuals)
Two truths: “display value” vs “actual carried value”

fs_value is our cached display value (what we show on meter)

PD also has an internal “points carried” concept that can change via merges

So we do this:

On spawn / split / spill

We set fs_value ourselves and update the meter immediately.

On pickup / merge

We assume PD may change values, so we re-read or reconcile.

Because TF2 PD can be weird about “which entity owns the number” after merges, the safe strategy is:

Treat fs_value as “what this pickup is worth”

Treat “player’s carried total” as separate — we track it with State.LastCarryValue[player] and update it based on events.

Your doc already has LastCarryValue for clamp tracking, which is exactly the right pattern.

5) The merge problem (the real crux)

You described it perfectly:

“OnPickup can be either a merge event… detecting when a player already was carrying a flag and has picked up another”

The key insight

A “merge” is just: player already carrying, then picks up another pickup.

So you detect merge by comparing:

carryBefore = State.LastCarryValue[player]

pickup event arrives

after a short delay (0.0–0.05s), compute carryAfter

if carryAfter > carryBefore, then:

we consider that pickup entity “consumed into carry”

we should kill/recycle its visuals and return it to pool (or remove it) depending on how PD leaves it

Where do we get carryAfter?

Event-driven ideal:

teamplay_flag_event gives you that something happened with a flag (pickup/drop/return etc). 

tf2_events

Then you compute the player’s carried amount using your own bookkeeping:

on pickup, carryAfter = min(CARRY_MAX, carryBefore + pickedFlag.fs_value)

then clamp/overflow logic to fuel (your doc’s carry clamp rule) 

README

This means we don’t have to rely on fragile netprops for carried value; we treat our value model as authoritative, while PD provides the tactile behavior.

Yes, this is “coding for merge,” but only for tracking + visuals — not to force PD to merge. PD still merges physically; we just compute what it must have merged by using the picked flag’s value.

Why this works in practice

Because in your gamemode:

Every pickup that matters is script-managed (fs_isFlagspawn)

Every script-managed pickup has a known value (fs_value)
So the merge math is deterministic even if PD hides details.
